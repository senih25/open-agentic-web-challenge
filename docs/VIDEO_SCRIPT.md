# TrustMesh — 90-second demo video script

**Target runtime:** 1:35–1:45
**Language:** English
**Recording:** the entrant must personally record the narration and browser footage. Do not use synthetic narration or represent the deterministic local mock as a real model.

## Before recording

1. Use the public production pages:
   - https://trustmesh-agentic-web.pages.dev
   - https://trustmesh-open-housing-guide.pages.dev
2. Configure a real provider key yourself in the TrustMesh browser settings. Never show or record the key, settings field, provider secret, or account details.
3. Run one successful real-model task that actually discovers the partner, displays both consent stages, invokes the read-only peer action and produces a receipt.
4. Confirm that the page does not display “EXAMPLE LLM — no real model” or the “demo model” status. If a real provider-backed peer call does not complete, do not imply that it did; record only the verified product areas and list the live-call limitation.
5. Use a clean browser profile, hide personal tabs/notifications, and use synthetic non-personal request text. The partner dataset is fictional; say so on screen and in narration.

## Timed shot list and narration

| Time | Browser footage | Spoken narration |
|---|---|---|
| 0:00–0:10 | TrustMesh production landing page; keep the URL visible. | “AI agents can work across websites. But collaboration should never mean giving every website unrestricted access to a user's data.” |
| 0:10–0:20 | Show TrustMesh and then the independent Open Housing Guide tab with its different HTTPS origin. | “TrustMesh is a browser-native agent network. It connects two independently published websites while keeping the user in control.” |
| 0:20–0:33 | Return to TrustMesh; submit a short synthetic housing-information request using the real provider-backed session. | “I start with a request on TrustMesh. Its browser runtime validates the published partner network before it can be used.” |
| 0:33–0:47 | Show the origin/discovery approval card. Pause long enough to read the target site and purpose, then approve. | “First, I review the destination and approve discovery. Permission to inspect a public network is not permission to send my information.” |
| 0:47–1:02 | Show the field-level disclosure review. Point out what is shared and what is withheld; approve only the necessary fields. | “Next, I review the exact fields for this request. Only the information I approve is projected into the partner payload. Private browser context and provider credentials stay out of the handoff.” |
| 1:02–1:15 | Show the partner result and identify it as fictional sample guidance. | “The independent Open Housing Guide returns read-only sample information. It does not decide eligibility or submit an application.” |
| 1:15–1:28 | Show the disclosure/execution receipt, its shared and withheld fields, and digest values. | “TrustMesh records the decision and result as a redacted receipt. It gives the user inspectable evidence without storing the sample field values.” |
| 1:28–1:40 | Show the repository README, compliance matrix and public smoke-test evidence. | “The project includes a pinned challenge profile, repeatable two-origin checks and documented security boundaries. TrustMesh makes agent collaboration explicit, scoped and reviewable.” |
| 1:40–1:45 | End card with the two public URLs and repository URL. | “TrustMesh. Open collaboration, with user-controlled delegation.” |
